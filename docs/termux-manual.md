# Android/Termux Manual — Neutrino

## What this manual is

Covers using `neutrino` inside **Termux**, a Linux terminal emulator for Android: the same TUI binary (bubbletea) as Linux/macOS, running inside a real Linux userland on the phone — not a native graphical app. This is a different path from the native Android app with a Fyne graphical UI (in testing, not distributed yet): here there is no graphical UI, only the terminal, with a text interface identical to the desktop one.

For using `neutrino` once it's running (commands, tabs, groups, backup, message signing...) `user-manual.md` applies in full — this document covers only what is specific to the Termux environment: installing it, updating it, maintaining it, and configuring it for a solid experience.

---

## Termux: what it is and where to install it from

Termux provides a complete Linux environment (its own `pkg`/`apt` package manager, its own `$HOME`) on top of Android, without root. **The only source to use is [F-Droid](https://f-droid.org/packages/com.termux/)** (or the `.apk` file directly from the [GitHub releases](https://github.com/termux/termux-app/releases)):

- **The Google Play version is deprecated and abandoned by the Termux developers themselves** (since 2021, due to technical limits Google imposes on apps of this kind — outdated packages, updates that stop working). **Do not install it.**
- Requirement: Android 7 or later; arm64 architecture recommended (the same one `neutrino-ux-arm64-v<version>-b<build>` is built for).

Additional useful apps, also from F-Droid (same repository/family as Termux — never mix with the Play Store version):

| App | What it's for |
|---|---|
| **Termux:API** | `termux-*` commands for camera, clipboard, notifications, battery — optional, see below |
| **Termux:Boot** | Runs a script when the phone boots — essential for automatic startup, see "Automatic startup" |
| **Termux:Styling** | Color themes and fonts for the terminal (including Nerd Fonts, recommended — see "Fonts and symbols") |

## Updating and maintaining Termux

Do this right after installing, and periodically:

```bash
pkg update && pkg upgrade
```

Other useful maintenance commands:

```bash
termux-setup-storage   # grants Termux access to the phone's shared storage (~/storage/shared)
pkg autoclean           # removes downloaded .deb packages no longer needed
pkg clean               # also cleans apt's cache
df -h $PREFIX           # space used by the Termux installation
```

`termux-setup-storage` only needs to run once (requires the Android "Files and media" permission, to confirm in the system popup) — needed later to get backup/QR files generated by `neutrino` out of Termux.

**Backing up Termux itself**: `pkg upgrade` never touches `$HOME` (only installed packages), so it's safe to run without special precautions. What does **not** survive uninstalling Termux or a "Clear data" from Android settings is all of `$HOME`, including `~/.config/neutrino/keystore` — see "Backing up the Neutrino identity" below for how to protect it separately.

## Installing Neutrino

### 1. Get the binary

Two paths:

- **Precompiled binary** `neutrino-ux-arm64-v<version>-b<build>` (static, Tor + i2pd embedded — no extra system dependency required; the name always carries the current version and build, see `neutrino-manifest` for the exact one of the release you downloaded). Transfer it to the phone (cable/ADB, cloud, or download it directly inside Termux if the distribution URL is reachable).
- **Build it from source**, if you'd rather not trust someone else's binary: requires the Go toolchain, not available natively on Termux for a static build identical to the official one (the build uses Docker/Alpine for Tor and i2pd, not available on Android) — in practice it still needs to be built on a Linux/macOS PC with `bash build_neutrino.sh ux-arm` and then transferred, not built *inside* Termux.

### 2. Verify authenticity

Same procedure as the general user manual, identical commands on Termux (after `pkg install gnupg`, see below). If you also transferred `neutrino-manifest`/`neutrino-manifest.asc` alongside the binary:

```bash
gpg --verify neutrino-manifest.asc neutrino-manifest
sha256sum -c neutrino-manifest
```

If you only have the binary itself (e.g. transferred alone over cable), it carries its own signature appended to the end of the file — see "Verifying the authenticity of the downloaded binary" in the user manual for the extraction commands.

If any check fails, do not run the binary.

### 3. Make it executable and place it

```bash
chmod +x neutrino-ux-arm64-v<version>-b<build>
mv neutrino-ux-arm64-v<version>-b<build> $PREFIX/bin/neutrino   # available as "neutrino" from any directory
```

`$PREFIX/bin` (`/data/data/com.termux/files/usr/bin`) is already in Termux's `PATH` — no other configuration needed.

### 4. First run

```bash
neutrino
```

The wizard described in `user-manual.md` § "First launch — configuration wizard" starts — identical on Termux. The keystore ends up in `~/.config/neutrino/keystore` (i.e. `/data/data/com.termux/files/home/.config/neutrino/keystore`), just like on any Linux system.

### Optional packages

| Package | Command | What for |
|---|---|---|
| `termux-api` | `pkg install termux-api` (also requires the Termux:API app installed) | Clipboard access (`termux-clipboard-get`/`termux-clipboard-set`), used by the TUI to copy text such as an identity URI — not required for basic use |

Reading QR codes with the camera (`/cnt-read-qrcode`, `neutrino add-bridges --camera`) uses the Linux V4L2 interface (`/dev/video*`), which Android doesn't expose to Termux: on Termux read QR codes from an image file instead.

There's no need to install **either** `tor` **or** `i2pd` from `pkg`: they're already embedded in the `neutrino-ux-arm64-v<version>-b<build>` binary (see the technical note at the bottom).

## Fonts and symbols

The interface uses Unicode symbols for status (`●` `✓` `⚠`, connection dots, verification checkmarks). Android's system font usually already displays them correctly; if you see boxes or wrong symbols instead:

1. Install **Termux:Styling** (F-Droid, see above). It's not a shell command (`termux-style` **does not exist** as a Termux command — that name, by coincidence, only belongs to unofficial third-party scripts not covered here): use it with a long press anywhere on the terminal → **More...** → **Style** → **CHOOSE FONT** (or **CHOOSE COLOR** for the color theme).
2. Alternatively, without the app: download a font with good Unicode coverage — a monospace **Nerd Font** is recommended (e.g. "FiraCode Nerd Font", "Hack Nerd Font"), which also covers glyphs used by other TUIs besides Neutrino — save it as `~/.termux/font.ttf` and run `termux-reload-settings`.

## Keyboard: the extra-keys row

Android's software keyboard normally has no **Esc**, **Tab**, **Ctrl**, arrow, or **Page Up/Down** keys — **all used by the TUI** (dismissing a popup, moving between tabs, scrolling the chat). Termux shows a row of extra keys above the keyboard, configurable in `~/.termux/termux.properties`:

```properties
extra-keys = [[ \
    {key: ESC}, {key: TAB}, {key: CTRL}, \
    {key: UP}, {key: DOWN}, {key: LEFT}, {key: RIGHT}, \
    {key: PGUP}, {key: PGDN} \
]]
```

After editing the file:

```bash
termux-reload-settings
```

Without this row (or a physical/Bluetooth keyboard attached) several TUI commands are effectively unusable — this is the single most important configuration in this document for comfortable use.

## Keeping Neutrino active in the background

If your device hosts a room (active Tor/I2P hidden service) or you simply want to stay reachable with the screen off, you need to prevent Android from suspending the process:

1. **Wake lock — automatic, nothing to run**: `neutrino` itself acquires a wake lock (`termux-wake-lock`) as soon as the TUI starts and releases it (`termux-wake-unlock`) on exit — no manual command needed. This only has an effect on Termux; the same binary runs unchanged on Linux/macOS, where it's a silent no-op.

2. **Excluding Termux from Android's battery optimization**: Settings → Apps → Termux → Battery → "Unrestricted" (the exact wording varies by manufacturer: Samsung, Xiaomi/MIUI, Huawei, and OnePlus have additional, more aggressive battery managers on top of plain Android — on these manufacturers you also need to disable the manufacturer-specific "optimizer", not just the standard Android setting). Without this step, the wake lock alone often isn't enough: the system can still kill the process after a few minutes with the screen off.

3. **Persistent notification**: Termux normally shows a persistent notification ("Termux" in the status bar) while a session is open — this is a signal to Android that the process is still actively in use, in addition to the wake lock. Don't disable it to "clean up" the notification bar: it's part of what keeps the session alive.

**Honest limitation**: even with all of the above, Android remains a mobile operating system designed to suspend background apps — it is not the equivalent of an always-on Linux server. Under very low battery ("extreme power saving") the system can still terminate any process, wake lock included. For a host that needs to stay reliably reachable 24/7, a Linux desktop/VPS remains the sturdier choice; Termux is suited to "phone-style" use, not to replacing an always-on node.

## Automatic startup (Termux:Boot)

There is no `systemd` on Android — `neutrino install` (designed for Linux desktop, see `user-manual.md` § "Auto-start (systemd)") doesn't apply here. The Termux equivalent is **Termux:Boot** (separate app, F-Droid — see above):

1. Install the Termux:Boot app and open it at least once (requires the Android autostart permission, which some manufacturers hide in an extra menu — look for "Autostart" in the app settings if the permission doesn't show up on first launch).
2. Create a startup script:
   ```bash
   mkdir -p ~/.termux/boot
   cat > ~/.termux/boot/start-neutrino.sh <<'EOF'
   #!/data/data/com.termux/files/usr/bin/sh
   neutrino
   EOF
   chmod +x ~/.termux/boot/start-neutrino.sh
   ```
3. From now on, every phone reboot runs the script automatically (Termux:Boot starts Termux in the background even if the app was never opened manually).

Note: `neutrino` on first run is an interactive wizard (see above) — the boot script only makes sense **after** the first run has already been completed manually at least once (the wizard can't be completed "blind" by a non-interactive script).

## Backing up the Neutrino identity (and why it matters more on Termux)

The 24-word BIP-39 backup (`neutrino backup`, see `user-manual.md` § "Identity backup and restore") works identically on Termux — but here accidentally uninstalling Termux, a "Clear data" from Android settings, or simply replacing the phone will delete `~/.config/neutrino/keystore` **with no system warning at all** (unlike a PC, where the file stays on disk even after uninstalling a program). Running `neutrino backup` and taking the 24 words (on paper, or elsewhere) off the phone itself matters more here than on desktop.

To get the generated files (backup PNG, `.chunk` files) out of Termux and into the phone's shared storage (from where they can then be moved via cable, cloud, etc.):

```bash
termux-setup-storage   # once, see above
cp neutrino-backup-* ~/storage/shared/Download/   # .bin, .png and .chunk files
```

**Note on QR codes when the device is already the phone**: the identity or backup QR code is meant to be photographed by **another** device (a contact, or your PC). Photographing the same phone's screen with the same phone's camera makes no practical sense — on Termux it's always better to use the `.chunk` file directly (raw text, generated next to the PNG by `neutrino backup`/`neutrino sync export`) to move data to another device, instead of going through the QR code.

## Updating Neutrino

There is no `neutrino update` command. Updating means repeating steps 1-3 of "Installing Neutrino" with a newer `neutrino-ux-arm64-v<version>-b<build>` binary, overwriting the one at `$PREFIX/bin/neutrino`. The keystore (`~/.config/neutrino/keystore`) is not touched by this operation.

---

## Technical note: why the arm64 binary needs no system packages

`neutrino-ux-arm64-v<version>-b<build>` bundles Tor and i2pd as **static** binaries (musl/Alpine build, same scheme as the linux/amd64 build) — a truly static binary doesn't depend on the dynamic linker of the system running it, so it runs identically under Termux (which uses Bionic, Android's libc, not glibc/musl) without needing `pkg install tor i2pd`. obfs4/webtunnel bridges (see `user-manual.md` § "Tor bridges — terminal commands") have no `lyrebird` binary to bundle: pluggable transports run in-process, compiled together with the rest of the `neutrino` binary itself — no architectural limitation on this platform.

## Common troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `Permission denied` when starting `neutrino` | Missing execute permission after transferring the file | `chmod +x $PREFIX/bin/neutrino` |
| `●`/`✓`/`⚠` symbols shown as boxes | Font with no Unicode coverage | See "Fonts and symbols" |
| Esc/Tab/arrow keys not available | Software keyboard without extra-keys configured | See "Keyboard: the extra-keys row" |
| Tor/i2pd fail to bootstrap, or the connection drops with the screen off | Android battery optimization/Doze | See "Keeping Neutrino active in the background" |
| After a phone reboot Neutrino doesn't restart on its own | Termux:Boot not installed/not authorized, or autostart permission denied by the manufacturer | See "Automatic startup" |
| The keystore is gone after uninstalling/reinstalling Termux | `$HOME` doesn't survive uninstallation — expected Android behavior, not a bug | Restore from backup, see "Backing up the Neutrino identity" |
